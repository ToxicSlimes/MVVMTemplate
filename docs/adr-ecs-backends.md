# ECS-бэкенды MVVMTemplate

Статус: решение принято; реализация и проверка обоих вариантов выполняются.

## Контекст

Шаблон используется проектом PowerWash с Morpeh. Новому проекту нужен StaticEcs. Публичные модели сущностей, запросов и систем этих библиотек различаются; общий фасад над ними скроет существенные различия и не даст переносить геймплей автоматически.

## Решение

- В игровом коде используется API выбранного ECS. Общий слой не оборачивает сущности, фильтры, компоненты и системы.
- Границу композиции и жизненного цикла можно разделить между бэкендами: регистрация зависимостей, запуск и остановка мира. Бэкенд-специфичные фичи и репозитории остаются отдельными.
- Целевые конфигурации выбирают `MORPEH` либо `STATIC_ECS`; оба символа одновременно недопустимы. Конфигурация без символов может использоваться для промежуточной проверки изоляции, но не является готовой конфигурацией игры.
- Morpeh остаётся совместимым вариантом для PowerWash. Условная компиляция сборок шаблона сама по себе не отключает автоинициализацию отдельно установленного пакета Morpeh: это необходимо учитывать при настройке StaticEcs.
- StaticEcs использует статический мир на marker-тип. Владелец должен контролировать создание, обновление и очистку; `Systems.Add` не следует использовать для динамического добавления после инициализации pipeline. Динамическое включение фич требует отдельного решения и тестов, а не подмены семантики Morpeh.

## Проверка перед завершением

Нужны реальные сборка и тесты обоих вариантов, жизненный цикл мира, повторный вход в Play Mode при отключённом domain reload, совместимость PowerWash и player-сборка IL2CPP/WebGL с учётом stripping. Решение о том, какие системы и модели синхронизации использовать в сетевой игре, принимается отдельно. До успешных проверок этот документ не подтверждает работоспособность конкретной реализации.
