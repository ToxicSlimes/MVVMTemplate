# MainView — Главный экран игры

## Обзор

MainView — основной экран приложения. Отображает героев игрока, их характеристики, ресурсы
и предоставляет доступ к ключевым игровым действиям: тренировка, лечение, управление командой.

**Для кого:** геймдизайнеры, которые хотят понять структуру главного экрана и его возможности.

---

## Как попасть на экран

```
Login → MenuSelection → кнопка "Main" → MainState → MainView
```

1. Авторизуйтесь на экране Login
2. На экране **MenuSelection** нажмите кнопку перехода к Main
3. Приложение переключится в `MainState`, который покажет `MainView`

## Пользовательские сценарии

### Сценарий 1: Просмотреть героев и выбрать

1. На экране отображаются слоты всех героев (сейчас 3 тестовых)
2. Каждый слот показывает: **имя**, **уровень**, **полоску здоровья**
3. Нажмите на слот героя — он станет **выбранным** (выделен визуально)
4. Панель **Stats** обновится характеристиками выбранного героя

```
Клик на слот ──► SelectHeroCommand ──► Model.SelectHero() ──► Heroes ReactiveProperty ──► UI обновлён
```

### Сценарий 2: Открыть грид героев

1. Нажмите одну из кнопок: **Upgrades**, **Healing** или **Team Management**
2. Откроется **HeroesGridPanel** — встроенная панель со списком всех героев
3. В гриде есть **3 вкладки**: Мои герои, Магазин, Погибшие
4. Выберите героя в гриде — действие зависит от режима (см. ниже)

| Кнопка | Режим | Что происходит при выборе героя |
|--------|-------|--------------------------------|
| **Upgrades** | `HeroesGridMode.Upgrades` | Открывается **TrainingPanel** для тренировки |
| **Healing** | `HeroesGridMode.Healing` | Открывается **HealingPanel** для лечения |
| **Team Management** | `HeroesGridMode.TeamManagement` | Открывается **HeroDetailPanel** с деталями |

### Сценарий 3: Тренировка / лечение героя

1. Нажмите **Upgrades** или **Healing**
2. В гриде выберите героя
3. Автоматически откроется соответствующая встроенная панель:
   - **TrainingPanel** — улучшение характеристик героя
   - **HealingPanel** — восстановление здоровья

```
Кнопка Upgrades ──► HeroesGridPanel (Upgrades mode)
                          │
                    выбор героя
                          │
                          ▼
                    TrainingPanel (с контекстом выбранного героя)
```

### Сценарий 4: Открыть настройки

1. Нажмите кнопку **Settings**
2. Откроется **SettingsView** — отдельный экран настроек (не embedded)
3. Настройки открываются через `ShowViewRequest<SettingsView, SettingsViewModel>`

## Элементы UI

### HeroSlotElement

Слот героя в верхней части экрана.

| Поле | Тип | Описание |
|------|-----|----------|
| `HeroId` | string | Уникальный ID героя |
| `Name` | string | Имя героя (отображается в слоте) |
| `Portrait` | Texture | Портрет героя (может быть null) |
| `Level` | int | Уровень героя (показывается как "Lv.45") |
| `IsSelected` | bool | Выделен ли слот |
| `IsDead` | bool | Мёртв ли герой (показывается overlay) |
| `HealthPercent` | float | Процент здоровья (заполнение полоски, 0.0–1.0) |

При нажатии на слот вызывается `SelectHeroCommand` с `HeroId`.

### StatRowElement

Строка характеристики в панели статов.

| Поле | Тип | Описание |
|------|-----|----------|
| `StatId` | string | ID характеристики |
| `Label` | string | Название (Сила, Ловкость...) |
| `Value` | string | Текстовое значение ("150/200") |
| `Icon` | Sprite | Иконка характеристики (может быть null) |
| `BarPercent` | float? | Заполнение прогресс-бара (null = скрыть бар) |

StatRow обновляется через **Reconciliation** — только изменённые строки перерисовываются.

### ResourceItemElement

Ресурс игрока (золото, кристаллы, энергия).

| Поле | Тип | Описание |
|------|-----|----------|
| `ResourceId` | string | ID ресурса (совпадает с Type) |
| `Name` | string | Название ресурса |
| `Amount` | int | Количество (форматируется с разделителями: 15,420) |
| `Description` | string | Описание (показывается в tooltip) |
| `Icon` | Sprite | Иконка ресурса (может быть null) |

## Встроенные панели (Embedded Views)

MainView содержит 4 встроенные панели, которые показываются/скрываются по запросу:

| Панель | ViewModel | Когда появляется |
|--------|-----------|-----------------|
| **HeroesGridPanel** | `HeroesGridPanelViewModel` | Кнопки Upgrades / Healing / Team Management |
| **HeroDetailPanel** | `HeroDetailPanelViewModel` | Выбор героя в режиме Team Management |
| **HealingPanel** | `HealingPanelViewModel` | Выбор героя в режиме Healing |
| **TrainingPanel** | `TrainingPanelViewModel` | Выбор героя в режиме Upgrades |

### HeroesGridPanel — подробнее

Грид с карточками героев. Содержит **3 вкладки**:

| Вкладка | Enum | Описание |
|---------|------|----------|
| **Мои герои** | `HeroesGridTab.MyHeroes` | Герои игрока |
| **Магазин** | `HeroesGridTab.Shop` | Герои для покупки |
| **Погибшие** | `HeroesGridTab.DeadHeroes` | Умершие герои |

Данные карточки героя в гриде (`HeroData` из `Core.Data.Domain.Models.Heroes`):

| Поле | Тип | Описание |
|------|-----|----------|
| `Id` | string | Уникальный ID |
| `Name` | string | Имя героя |
| `Class` | string | Класс (Warrior, Mage и т.д.) |
| `Level` | int | Уровень |
| `Health` / `MaxHealth` | int | Текущее / макс. здоровье |
| `IsSelected` | bool | Выбран ли |
| `IsNew` | bool | Новый герой (значок) |
| `NotificationCount` | int | Количество уведомлений |
| `HealthPercent` | float | Процент здоровья (computed) |
| `IsDead` | bool | Мёртв ли герой (computed) |

## Архитектура

```
┌─────────────┐    ┌──────────────┐    ┌─────────────────┐
│    View     │───►│  ViewModel   │───►│    Mediator     │
│  MainView   │    │ MainViewModel│    │                 │
│             │    │              │    │ Send/Publish    │
│ - кнопки   │    │ - Commands   │    │                 │
│ - слоты    │    │ - Properties │    │                 │
│ - статы    │    │              │    │                 │
└─────────────┘    └──────┬───────┘    └────────┬────────┘
       ▲                  │                      │
       │                  ▼                      ▼
       │           ┌──────────────┐    ┌─────────────────┐
       │           │    Model     │    │    Handlers     │
       │           │  MainModel   │    │ (Application)   │
       │           │              │    │                 │
       │           │ - heroes     │    │ Show/Hide       │
       │           │ - stats      │    │ EmbeddedView    │
       │           │ - resources  │    │ Navigate        │
       │           └──────────────┘    └─────────────────┘
       │                  │
       │     events       │
       └──────────────────┘
```

### Поток данных

1. `MainModel.LoadData()` загружает данные (сейчас тестовые)
2. Model вызывает события: `HeroesChanged`, `StatsChanged`, `ResourcesChanged`
3. ViewModel обновляет `ReactiveProperty` → View получает обновления через `Subscribe`
4. View рендерит элементы через **Mediator CQRS**:
   - `CreateElementRequest<HeroSlotElement, HeroSlotData>` — создание слота героя
   - `ReconcileElementsRequest<StatRowElement, StatRowData>` — обновление статов (diff-based)
   - `ReconcileElementsRequest<ResourceItemElement, ResourceItemData>` — обновление ресурсов

### Навигация через Mediator

| Действие | CQRS запрос |
|----------|-------------|
| Открыть настройки | `ShowViewRequest<SettingsView, SettingsViewModel>` |
| Открыть грид героев | `ShowEmbeddedViewRequest<HeroesGridPanelViewModel>` |
| Показать тренировку | `ShowEmbeddedViewRequest<TrainingPanelViewModel>` |
| Показать лечение | `ShowEmbeddedViewRequest<HealingPanelViewModel>` |
| Показать детали героя | `ShowEmbeddedViewRequest<HeroDetailPanelViewModel>` |

## Persistent View

MainView помечен как `IsPersistent => true`. Это означает:

- View **не уничтожается** при переходе на другие экраны
- При возврате на MainState View показывается заново без пересоздания
- Данные и состояние сохраняются между переходами
- Встроенные панели (HeroesGridPanel и др.) остаются зарегистрированными

Это важно для UX — пользователь возвращается к экрану в том же состоянии, в котором его покинул.
