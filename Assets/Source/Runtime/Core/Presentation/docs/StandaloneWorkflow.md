# Standalone Workflow — Экран управления воркфлоу

## Обзор

Standalone Workflow — экран для запуска и взаимодействия с серверными воркфлоу (workflow).
Позволяет выбрать воркфлоу из списка, выполнить его, загрузить процедурный UI и взаимодействовать
с динамически сгенерированными компонентами (кнопки, формы, карточки и др.).

**Для кого:** геймдизайнеры, которые настраивают воркфлоу на бэкенде и хотят увидеть результат в клиенте.

---

## Как попасть на экран

```
Login → MenuSelection → кнопка "Standalone Workflow" → StandaloneWorkflowState → StandaloneWorkflowView
```

1. Авторизуйтесь на экране Login
2. На экране **MenuSelection** нажмите кнопку перехода к Standalone Workflow
3. Приложение переключится в `StandaloneWorkflowState`, который покажет `StandaloneWorkflowView`

### Элементы управления

| Элемент | Описание |
|---------|----------|
| **Dropdown воркфлоу** | Выпадающий список доступных воркфлоу. Показывает название и ID |
| **Refresh** | Загружает/обновляет список воркфлоу с сервера |
| **Execute** | Выполняет выбранный воркфлоу и отображает результат |
| **Get UI** | Загружает текущее состояние UI воркфлоу (без выполнения) |
| **Clear UI** | Очищает все процедурные компоненты с экрана |
| **Storage Type** | Переключает контекст хранилища: User или Session |
| **Session ID** | Идентификатор сессии (виден только при Storage Type = Session) |
| **Back** | Возврат к экрану MenuSelection |

## Пользовательские сценарии

### Сценарий 1: Загрузить список воркфлоу и выполнить

1. Нажмите **Refresh** — загрузится список воркфлоу с бэкенда
2. Выберите нужный воркфлоу в **Dropdown**
3. Нажмите **Execute** — воркфлоу выполнится на сервере
4. Если воркфлоу возвращает UI-компоненты, они появятся в контейнерах

```
┌──────────┐      ┌──────────┐      ┌──────────┐      ┌──────────┐
│ Refresh  │─────►│ Dropdown │─────►│ Execute  │─────►│ UI       │
│ (список) │      │ (выбор)  │      │ (запуск) │      │ (рендер) │
└──────────┘      └──────────┘      └──────────┘      └──────────┘
```

### Сценарий 2: Загрузить UI воркфлоу

1. Выберите воркфлоу в Dropdown (или нажмите Refresh сначала)
2. Настройте **Storage Type** (User или Session)
3. Нажмите **Get UI** — загрузится текущее состояние UI без выполнения воркфлоу
4. Компоненты появятся в соответствующих контейнерах

⚠️ **Get UI** не выполняет воркфлоу — только загружает сохранённое состояние UI.

### Сценарий 3: Взаимодействие с процедурным UI

1. После загрузки UI (через Execute или Get UI) в контейнерах появятся компоненты
2. Нажмите на кнопку, заполните форму, выберите значение в dropdown — действие отправится на сервер
3. Сервер обработает действие и вернёт обновлённый UI
4. Компоненты автоматически обновятся

```
Пользователь ──клик──► UI Component ──action──► Backend ──response──► Обновлённый UI
```

### Сценарий 4: Переключить контекст хранилища

1. В **Storage Type** выберите "Session"
2. Появится поле **Session ID** — введите ID сессии
3. Теперь **Get UI** и **UI Action** будут работать в контексте указанной сессии
4. Переключите обратно на "User" для работы с пользовательским хранилищем

## Типы UI-компонентов

## Placement (расположение компонентов)

Каждый компонент имеет свойство `placement`, которое определяет, где он будет отрисован:

| Placement | Контейнер | Описание |
|-----------|-----------|----------|
| `sidebar` | Левая панель | Боковая панель, навигация, меню |
| `below_chat` | Основная область (Main) | Главный контент экрана |
| `above_input` | Над вводом | Подсказки, промежуточные результаты |
| `modal` | Модальное окно | Всплывающие диалоги |

```
┌──────────────┬──────────────────────────┐
│   sidebar    │       below_chat         │
│              │                          │
│              │                          │
│              ├──────────────────────────┤
│              │       above_input        │
└──────────────┴──────────────────────────┘

         ┌──────────────────────┐
         │        modal         │
         │   (поверх всего)     │
         └──────────────────────┘
```

Если placement не указан, компонент размещается в `sidebar` по умолчанию.

## Storage Context (контекст хранилища)

| Тип | Описание | Когда использовать |
|-----|----------|--------------------|
| **User** | Данные привязаны к пользователю | Постоянные настройки, общие данные между сессиями |
| **Session** | Данные привязаны к сессии | Временные данные в рамках одной сессии игры |

- При выборе **Session** необходимо указать `Session ID`
- Если `Session ID` не указан, сервер создаст новую сессию
- При выборе **User** поле `Session ID` скрывается — данные привязаны к аккаунту

## Типы действий (Action Types)

Когда пользователь взаимодействует с компонентом (нажимает кнопку, заполняет форму), отправляется действие:

| Тип действия | Описание |
|--------------|----------|
| `trigger_workflow` | Запустить другой воркфлоу |
| `send_message` | Отправить сообщение в чат |
| `insert_text` | Вставить текст в поле ввода |
| `execute_command` | Выполнить серверную команду |
| `save_to_storage` | Сохранить данные в хранилище |
| `open_url` | Открыть внешнюю ссылку |
| `close_modal` | Закрыть модальное окно |

## Ошибки

| Код ошибки | Описание | Что делать |
|------------|----------|------------|
| `WORKFLOW_NOT_FOUND` | Воркфлоу не найден на сервере | Проверьте, что воркфлоу существует и опубликован |
| `ENTRYPOINT_NOT_FOUND` | Точка входа `STANDALONE_TRIGGER` не найдена | Добавьте STANDALONE_TRIGGER в триггеры воркфлоу |
| `ACCESS_DENIED` | Нет доступа к воркфлоу | Проверьте права доступа на бэкенде |
| `CONTEXT_ERROR` | Ошибка контекста хранилища | Проверьте настройки Storage Type и Session ID |
| `VALIDATION_ERROR` | Данные не прошли валидацию | Проверьте корректность введённых данных |
| `EXECUTION_ERROR` | Ошибка при выполнении воркфлоу | Проверьте логику воркфлоу на бэкенде |

⚠️ Текст ошибки отображается красным в области **Статус** под кнопками.

## Архитектура (для понимания)

Упрощённая диаграмма: что происходит при нажатии кнопки **Execute**.

```
┌─────────────┐    ┌──────────────┐    ┌─────────────────┐    ┌──────────────┐    ┌──────────┐
│    View     │───►│  ViewModel   │───►│    Mediator     │───►│   Handler    │───►│ Backend  │
│ (кнопка    │    │ Execute      │    │                 │    │ (Application)│    │   API    │
│  Execute)   │    │ WorkflowAsync│    │ Send(Command)  │    │              │    │          │
└─────────────┘    └──────────────┘    └─────────────────┘    └──────────────┘    └──────────┘
                          │                                                            │
                          │◄────────────── Result (StandaloneUiResult) ◄───────────────┘
                          │
                          ▼
                   ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
                   │    Mapper    │───►│ UiComponent  │───►│  Render UI   │
                   │ (DTO→Model) │    │   Models     │    │ (в контейнеры│
                   └──────────────┘    └──────────────┘    └──────────────┘
```

### Слои

| Слой | Файл | Ответственность |
|------|-------|-----------------|
| **View** | `StandaloneWorkflowView.cs` | UI элементы, подписки на ViewModel |
| **ViewModel** | `StandaloneWorkflowViewModel.cs` | Логика экрана, команды, состояние |
| **Model** | `StandaloneWorkflowModel.cs` | Хранение данных, события изменений |
| **Application** | `ExecuteWorkflowCommand`, `GetWorkflowsQuery` | CQRS запросы/команды |
| **Data** | `StandaloneUiResult.cs`, `StorageContext.cs` | DTO и доменные модели |
| **Mapper** | `StandaloneUiMapper.cs` | Преобразование DTO → UI модели |

## Backend эндпоинты

| Действие | CQRS запрос | Что вызывается |
|----------|-------------|----------------|
| Загрузить список воркфлоу | `GetWorkflowsQuery(page, pageSize)` | GET /workflows (с пагинацией) |
| Выполнить воркфлоу | `ExecuteWorkflowCommand(workflowId)` | POST /workflows/{id}/execute |
| Загрузить UI воркфлоу | `GetWorkflowUiQuery(workflowId, storageContext)` | GET /workflows/{id}/ui |
| Выполнить UI-действие | `ExecuteWorkflowUiActionCommand(workflowId, payload, storageContext)` | POST /workflows/{id}/ui/action |

### Фильтрация воркфлоу

Не все воркфлоу отображаются в списке. Показываются только те, у которых есть активный триггер
с точкой входа `STANDALONE_TRIGGER`. Это настраивается на бэкенде при создании воркфлоу.
